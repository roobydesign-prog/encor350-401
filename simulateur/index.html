Lab 1: OSPFv2 Multi-Area, Summarization & DR Election

Configure OSPF area range summarization on ABR and force DR election using IP interface priority.

! Router ABR (R1) enable configure terminal router ospf 1 router-id 1.1.1.1 area 1 range 10.1.0.0 255.255.0.0 exit interface GigabitEthernet0/1 ip ospf priority 255 end write memory

Lab 2: Multi-AS BGP Peering & IPv4 Address-Family

Configure eBGP session explicitly disabling default IPv4 unicast and enabling address-family activation.

! Router R100 (AS 100) enable configure terminal router bgp 100 bgp router-id 10.0.0.1 no bgp default ipv4-unicast neighbor 192.168.12.2 remote-as 200 ! address-family ipv4 neighbor 192.168.12.2 activate network 10.0.0.1 mask 255.255.255.255 exit-address-family end

Lab 3: Python Automation via NETCONF (ncclient)

Script to connect via SSH port 830 and extract running configuration in XML format.

from ncclient import manager device_info = { 'host': '192.168.1.1', 'port': 830, 'username': 'admin', 'password': 'CiscoPassword123!', 'hostkey_verify': False, 'device_params': {'name': 'csr'} } with manager.connect(**device_info) as m: xml_response = m.get_config(source='running') print(xml_response.data_xml)

2. YANG Data Modeling Constructs

Leaf

Contains a single simple value (e.g. string, integer, boolean). Holds no child nodes.

Leaf-list

Contains an array/sequence of scalar values of a defined type.

Container

Used to group related nodes together in a subtree. Holds no value itself.

List

Defines a sequence of list entries, uniquely identified by key leaves.

Cisco SD-Access & SD-WAN Planes

  • SD-Access Control Plane: Uses LISP (Locator/ID Separation Protocol) to track endpoints.
  • SD-Access Data Plane: Uses VXLAN for data encapsulation and overlay transport.
  • SD-Access Policy Plane: Uses Cisco TrustSec (SGTs) for group-based policy enforcement.
  • SD-WAN Control Plane: Managed by vSmart controllers using OMP (Overlay Management Protocol).
  • SD-WAN Management Plane: Handled centrally by vManage.

REST API Status Codes

  • 200 OK: Request succeeded; returned payload data in body.
  • 201 Created: Resource successfully created on server.
  • 204 No Content: Request fulfilled successfully; no body returned (e.g., successful DELETE).
  • 400 Bad Request: Malformed request payload or syntax error.
  • 401 Unauthorized: Authentication credentials missing or invalid.
  • 403 Forbidden: Server understood request but refuses authorization.
  • 404 Not Found: Target resource URI does not exist.
